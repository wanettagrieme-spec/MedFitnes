# ICF SINGAPORE — правила для Claude Code

HTML-протокол осмотра МДРК на основе МКФ: один файл `app/icf-singapore.html` (~18,6 МБ), работает офлайн в браузере на MacBook, iPad, iPhone. 20+ шкал, «Окружение», графический профиль МКФ, реабилитационный диагноз, ИПМР, каталоги BTL, движок выбора физического фактора, журнал исходов. Владелица — врач ФРМ, автор программы и её главный ревьюер. Отвечать по-русски.

## Знания о проекте — в базе medfit-vault (метод Карпаты, безусловно)
База стоит над всеми проектами. Хук старта сессии сам находит её, подтягивает и выводит последние записи журнала. Перед работой по теме читать страницу базы, а не полагаться на память:
- `Вики/Проекты/ICF SINGAPORE — протокол.md` — состояние, история, открытые вопросы, «ДАЛЬШЕ»;
- `Вики/Проекты/ICF SINGAPORE — движок физиотерапии.md` — движок, дозогейтинг, источники;
- `Вики/Проекты/ICF SINGAPORE — печать и интерфейс.md` — печать, экранный вид, проверенные приёмы;
- `Вики/Понятия/Оцифровка энциклопедий BTL.md`, `Вики/Понятия/Проверка печати.md` — методы.
Правила самой базы — её `CLAUDE.md`. Любое действие по проекту фиксируется в базе (страница проекта «было → стало», `Журнал/ГГГГ-ММ-ДД.md`, строка в `log.md`), сессия закрывается только после «ГОТОВО» от `python3 _система/finish.py`. Хук остановки не даст закончить, пока этого нет.

## Как владелица работает — соблюдать всегда
1. **Изучить** материал глубоко (код, страницы базы, источник).
2. **Подтвердить понимание**: пересказать, что нашла, где в коде, что собираюсь менять и почему; перечислить, что проверить не смогу.
3. **Код не трогать без её явного сигнала** («делай», «применяй», «начинай с …»). Вопрос или обсуждение — не сигнал.
4. После каждой правки — `/proverka` (сам хук после правки уже прогоняет синтаксис встроенного JS).
5. **Отчитаться честно**: что сделано, чем проверено, что проверить не удалось. Свои ошибки признавать прямо.
Её замечания проверять эмпирически и признавать, если она права: она не раз находила то, что Claude пропускал («Затирает», аудит D01–D04, «где клавиша?»).

## Жёсткие правила кода
- **Файл никогда не переписывается целиком** (Write запрещён хуком): только точечные Edit. Полная перезапись ~18,6 МБ из контекста обрезает файл.
- **Навигация — Grep с номерами строк, Read с offset/limit.** Не читать файл целиком: в нём base64-фото атласа (ATLAS_EX) и огромные массивы данных.
- **Не гадать.** Источник не найден — спросить. Всё, что не взято из источника буквально, помечать в коде и в выводе: «экстраполяция», «вывод по каталогу», «допущение».
- **Не обобщать между технологиями.** У каждой своя физика: у магнита континуальное поле = ОСТРО, у микроволновой непрерывный режим = ХРОНИЧЕСКИ. `BTL_IND` = её xlsx «Синергия 4 технологий», совпадение 100 % — не трогать.
- **Движок не блокирует и не меняет выбор молча** (её правило с v2_96): только текст «СТОП:» / «требует решения врача», решение за врачом ФРМ.
- **Данные должны доходить до документа.** Класс дефектов v2_256/257: каталог есть, а в интерфейс/назначение/печать не попадает (`microwaveHtml` не присваивался; `ftHas` в `btlRxLines()` перечислял не все каталоги). Проверять путь данных настоящим кликом, а не наличием массива.
- **Печать живёт в трёх местах**: `#inlinePrintRoot` (предпросмотр), `@media print`, `standalonePrintCss()` (сохраняемый лист, префикс `.print-root` обязателен). Правка печати — во все три. Утверждения о печати доказываются PDF-прогоном (`/pechat`), а не чтением CSS.
- **Новое поле `protocol.*` → в фабрику пустой карты** (`freshProtocol/freshFunctional/freshRows/resetCaseState`), иначе оно переживёт «Новый пациент» (дефект D01).
- **Ключ хранилища `icfModule_v2_34` не менять никогда** — иначе пропадут сохранённые карты. Версии: `APP_VERSION` (ICF SINGAPORE NN), `DATA_SCHEMA`, `RULES_VERSION`, `versionStamp()`.
- **Цвета — для обеих тем.** Повторяющаяся ошибка файла: цвет, рассчитанный на тёмную панель, на светлой (белое по белому).
- **Смешанные глифы** в данных BTL («5 cм²» с латинской c, «Пр oгpa мм a»): поиск по-русски такие строки не находит. Нормализовать только служебные слова, значения брать из оригинала.
- Каждый блок рендера — в `btlSafe/btlFail` (try/catch), как у неё принято.
- Данные пациентов в тестах и базе — только обезличенно.

## Устройство папки
- `app/icf-singapore.html` — рабочий файл (имя постоянное; версия внутри файла и в git-метке `icf-NN`). Копии для iPad/Диска с именем «ICF SINGAPORE NN.html» делает `/vypusk`.
- `docs/КАРТА-КОДА.md` — где что в файле (функции, массивы, хранилища). Обновлять при каждом заметном изменении.
- `tests/` — самотест на Playwright: `node tests/selftest.mjs`, печать — `node tests/print_pdf.mjs`. Ожидания (функции, размеры каталогов) — `tests/expected.json`.
- `.claude/` — хуки, навыки, независимый ревьюер.

## Команды
- `/pravka <задача>` — полный цикл правки: изучить → подтвердить → ждать сигнала → править → проверить → отчёт.
- `/proverka` — самотест настоящими кликами + разбор отчёта.
- `/pechat` — PDF-прогон печатных форм, имитация чужого принтера и ч/б.
- `/sverka <каталог>` — сверка каталога BTL с PDF-источником запись в запись.
- `/vypusk` — новая версия ICF SINGAPORE NN: метка, GitHub, Диск, база.
- `/zapis` — зафиксировать сделанное в базе и закрыть сессию по Карпаты.
Для важных правок (движок, сохранение, печать) после своей проверки — независимый ревьюер: агент `nezavisimyj-revyu`, он не видел, как писалась правка.
