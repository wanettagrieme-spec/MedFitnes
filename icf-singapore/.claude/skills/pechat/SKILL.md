Утверждения о печати доказываются PDF, а не чтением CSS. Перед работой прочитай в базе страницу «ICF SINGAPORE — печать и интерфейс».

1. `node tests/print_pdf.mjs $ARGUMENTS` — по умолчанию A4 по стилям файла. Чужой принтер (iOS + Brother HL-L2340D у владелицы): `--printable=265`, затем `--printable=225`.
2. Прочитай `tests/out/print-report.md`. Красное:
   - **лист потерял заливки** — в `standalonePrintCss()` нет правил `.g-*` (класс v2_249); правила — с префиксом `.print-root`.
   - **страницы расходятся** — открыть оба PDF глазами: бывает задумано (у листа свои размеры шрифта), бывает признаком правки не во всех трёх местах.
3. **Смотри PDF глазами** (рендер страниц в PNG через pypdfium2 и Read): пустой первый лист, разрыв внутри блока графика, налезание — тест этого не ловит.
4. Ч/б: `tests/out/print/*.chb.png` — различимо ли «залито/пусто» после фильтра ксерокса.
5. Печать живёт в трёх местах: `#inlinePrintRoot`, `@media print`, `standalonePrintCss()`. Любая правка — во все три, затем повторить прогон.
6. В отчёте владелице: числа страниц до/после, что видно глазами, что не проверено (Safari на iPad печатает по-своему — это проверяет только она).
